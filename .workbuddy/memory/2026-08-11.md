# 2026-08-11

## nekosearch 项目初始化（已完成）
- 用 Rust 搭建对标 Google 的自建搜索服务器骨架；已创建公开仓库 https://github.com/neko233-com/nekosearch （`main` 分支已推送）。
- 架构：单二进制 `nekosearch`，`--role all` 默认单机全角色；集群可拆 `registry`/`crawler`/`indexer`/`searcher` 独立进程。
- 注册中心：内置零外部依赖的 `Registry` trait，`InMemoryRegistry`(进程内) + `HttpRegistryClient`(集群) 两种实现，统一管理爬虫执行器（注册/心跳/任务派发），支持水平扩容。
- 索引：`InMemoryIndexer`（进程内倒排索引，简化 TF-IDF），`Indexer` trait 同样有内存/HTTP 两套实现。
- 爬虫执行器：`CrawlerExecutor` trait + http/fs 两个示例，BFS 外链回灌。
- 部署：Dockerfile（多阶段）+ docker-compose.yml（单机 all）+ deploy.sh（自动 docker/cargo）+ .env.example（clap env 注入）。
- 文档：AGENTS.md（开发规范，约定测试/CI 只保留单机 `--role all` 基线）、PLAN.md（架构与路线图）。
- 约束落地：“测试必须只保留一个” => 仓库测试矩阵仅以单机全角色为唯一基线。
- 注意：沙箱环境无 Rust 工具链，代码按可编译标准编写但**未执行 `cargo build`**，需在本机验证。

## 打通搜索内容 + suggest + Phase 5 HA（用户说"都要"）
- 根因：之前"什么都搜不到"是因为索引数据只能靠爬虫爬外网种子进入，默认无 seeds 且检索端口(7800)只可读，索引始终为空。
- Feature A 打通内容（commit 23f8b58）：新增 `crates/node/src/demo.rs` 内置演示文档集；config 加 `seed_demo`、CLI `--seed-demo`/`NEKO_SEED_DEMO`，启动写入演示文档到索引（无需外网即可搜）；searcher 新增 `POST /docs`（与索引 7900 的 /docs 一致，对外端口可写）；新增 `scripts/verify.sh` / `verify.ps1` 一键构建+起服务+查 /search+断言非空。
- Feature B suggest（commit be33f60）：`Indexer` trait 加 `suggest(prefix,limit)`；InMemoryIndexer/SledIndexer/ShardedIndexer 分别实现（按文档频率降序）；索引(7900)与检索(7800)均暴露 `GET /suggest`；集群下 ShardedIndexer 跨分片主副本聚合；网页搜索框接 /suggest，防抖(150ms)下拉+键盘导航。
- Feature C Phase 5 HA（commit 待推送）：`InMemoryRegistry` 加 HA 状态(self_id/peers/peer_view/leader)与选主/心跳方法（core 内零网络）；node `registry::run_ha_loop` 每秒 ping 对端 /ping、剔除超时、按 {本节点}∪{在线对端} 字典序最小者选主；注册中心 HTTP 加 `GET /ping`，写请求在非 leader 时 307 重定向到 leader；`HttpRegistryClient` 支持多注册中心基址(逗号/空格)故障转移，reqwest 默认跟随 307；main 用 `advertise_addr`(0.0.0.0->127.0.0.1) 作为 self_id。config 加 `peers`；config.yaml.example 同步 seed_demo/peers。
- 文档同步：README 增 seed-demo/POST /docs/suggest/多注册中心 HA 章节与配置项；PLAN 阶段4/5 标记 [x]；AGENTS §3/§8 更新。
